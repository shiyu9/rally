# 言語の解析部品

`--code` でソースを渡したとき、仕様書に足される次の情報は、言語ごとの**解析部品**が作る。

- `実装:`・`@impl` で指した関数の実在の確認と、コードの抜粋
- モジュール結合図に足す、ファイルどうしの参照
- 第 15 章(環境変数・ファイルの書き込みと削除・止まる箇所・失敗をまとめて受ける箇所)

どの言語を調べるかは、**ソースのフォルダにあるファイルの拡張子で決まる。** 設定は要らない。
同梱している部品は次の 3 つ。

| 言語 | 拡張子 | 読み方 |
|---|---|---|
| Python | `.py` | 構文木(標準ライブラリの `ast`) |
| PowerShell | `.ps1` `.psm1` | 正規表現。明示的に書かれた形だけを拾う |
| Bash | `.sh` `.bash` | 正規表現。明示的に書かれた形だけを拾う |

部品の無い拡張子のファイルは、`実装:` に書いた名前がファイルの中にあるかだけを確かめる
(コードの抜粋・参照の線・第 15 章には出ない)。

## 言語を足す・差し替える

部品は **1 言語 1 ファイルの Python モジュール**で、次の場所から読み込む。後ろの場所ほど優先し、
同じ拡張子の同梱の部品を差し替えられる。

1. このスキルの `scripts/analyzers/`(同梱)
2. 原稿の隣の `.spec-analyzers/`(`docs/.spec-src.md` なら `docs/.spec-analyzers/`)
3. ビルドの `--analyzers <フォルダ>`(複数可)

プロジェクトに置いた部品は、ビルドのときに Python のコードとして実行される。出どころの分からない
部品を置かない。

## 部品の決まり

次の 6 つを持つこと。足りないとビルドが止まり、どれが足りないかを知らせる。

```python
NAME = "Ruby"                  # 第 15 章に出る言語の名前
EXTENSIONS = (".rb",)          # 受け持つ拡張子(小文字)

def locate(text, func):
    """関数 func の (開始行, 終了行)。無ければ None。行は 1 から数える。"""

def doc(text):
    """ファイルの先頭の説明の 1 行目。無ければ空文字。"""

def references(text):
    """このファイルが参照している相手の名前の一覧(ファイル名か、拡張子を除いた名前)。
    同じフォルダのファイルに当たるものだけが、モジュール結合図の線になる。"""

def facts(text):
    """[(種類, 行, 囲む関数の名前の並び, 内容)] の一覧。種類は次の 4 つ。
    "env"    環境変数を読む所。内容は変数の名前
    "effect" ファイルやフォルダを書く・消す所。内容は「削除(rm)」のような短い説明
    "stop"   止まる所(例外を上げる・0 以外で終了する)
    "broad"  失敗をまとめて受ける所"""
```

- 文法の誤りで読めないときは `SyntaxError` を上げる(どのファイルの何行目かを添えて止まる)
- 拾いすぎより、拾い落としのほうがましとは限らない。**拾えない形があることは第 15 章の冒頭に
  「明示的に書かれた箇所に限る」と出る**ので、確実に言えるものだけを返す
- 同梱の `_blocks.py` に、波かっこで関数を区切る言語のための小道具がある(`function_ranges`・
  `scan` など)。`powershell.py` と `bash.py` がその使い方の見本
